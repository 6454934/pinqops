Saving runs docker compose config first. A file compose will not parse is refused, and what is running is left exactly as it was.

Databases

The databases pinqops installed. A version upgrade dumps the data, starts the new version on its own volume, and loads the dump into it — the old container and its volume are left exactly as they were.

Mail

pinqops sends its own mail — alerts, and anything else it needs to tell you about — through a relay you provide.

This is a relay, not a mail server. pinqops does not receive mail, hold a queue, retry on its own schedule or sign anything. It hands a message to something that already speaks for a domain and reports what that something said.

DNS records

Mail sent from a domain with no SPF record and no DKIM signature does not bounce — it is accepted, filed as spam and never mentioned again. These are the records that prevent that.

Offsite copies

Copy every finished snapshot to an S3-compatible bucket — S3, Cloudflare R2, MinIO, Backblaze. The Object storage page uses these same credentials, so there is one place to rotate them.

Schedule a backup

Back up a database container or a docker volume on a schedule. Snapshots are kept under /opt/pinqops/backups; older ones are pruned to the retention count.

Schedule a job

Run a command on a schedule — a nightly dump, a cache sweep, a report. It runs either inside a container that is already up, or in a throwaway container from an image.

Each space-separated word becomes one argument, exactly as typed — there is no shell, so no quoting, no pipes and no redirection.

Dashboard preferences

Two-factor authentication

A six-digit code from an app on your phone, on top of your password. pinqops uses the standard one, so any authenticator app works.

Server time zone

The zone the server reports its local time in — what makes a timestamp here line up with docker logs and journalctl on the same box. The clock itself stays with NTP.

Servers

The Docker hosts this dashboard manages. “Default” is the server it runs on — most installs never need a second one. Another host is reached over SSH with a key stored here; that key is shell access, so it is encrypted at rest and the host’s key is pinned on first connect.

Add another server over SSH

The user needs to be in the docker group on that host — which is root-equivalent there. Get the host key with ssh-keyscan -t ed25519 <host> and paste the part after the hostname.

Dashboard password

API tokens

Tokens let AI agents and scripts drive the REST API — a Claude MCP server, an OpenAI function-calling tool, Codex, Cursor, or plain curl. Scope limits what a token can do.

Users & roles

Each user has a role: viewer (read-only), deployer (deploy & roll back), or admin (everything, including users). Roles map to the same permissions as API token scopes.

Invitations

Send somebody a link and let them pick their own password. The link works once and then stops. The role and the team are decided here, not by whoever follows it.
